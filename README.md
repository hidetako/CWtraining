# CW 交信トレーニング

ブラウザだけで動く、モールス符号（CW）の受信・送信・実戦運用の練習アプリです。
インストールもアカウント登録も API キーも不要で、`index.html` を開けばすぐ使えます。

FB NEWS の記事「[生成AIとCWで交信practice](https://www.fbnews.jp/202408/special2/index.html)」
（7M4MON 野村秀明氏）の着想と、CW コンテストシミュレーター
[Morse Runner](https://github.com/VE3NEA/MorseRunner)（VE3NEA）の設計を参考にしています。
元記事は Python + OpenAI API + ffmpeg の構成ですが、本アプリは交信シナリオをローカルで
生成し、音は Web Audio API で合成するため、外部サービスに一切依存しません。

## 使い方

操作方法は **[使い方説明書（docs/MANUAL.md）](docs/MANUAL.md)** にまとめています。
習熟度別のおすすめ順路、各タブの操作、キーボード操作の一覧、
困ったときの対処が載っています。

配布用の Word 版も同梱しています
（[CW交信トレーニング_使い方説明書.docx](docs/CW交信トレーニング_使い方説明書.docx)、A4 20 ページ）。
本文は Markdown 版が原本で、Word 版は次のコマンドで生成し直せます。

```bash
npm install docx
node docs/build-manual-docx.js
```

### ローカルで動かす

ES モジュールを使っているため、`file://` で直接開くとブラウザに読み込みを拒否されます。
簡易サーバー経由で開いてください。

```bash
python3 -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```

GitHub Pages などの静的ホスティングに置いた場合は、そのまま URL を開くだけで動きます。

## 機能

### 交信シミュレーター

CQ を出すところから `73` で終わるまで、ラバースタンプ QSO を一通り体験します。
習得段階に合わせて 3 つのスタイルがあります。

**ガイド付き模擬交信**（型を覚える段階）

各段階で「今どの局面か」「何のための送信か」を示し、自分が送る番では
**3 つの選択肢から選びます**。選ぶと、正解だけでなく他の選択肢がなぜ駄目なのかも
表示されます。距離のある間違い方ではなく、初心者が実際にやりがちな誤りを出します。

- 相手のコールサインを付けずに送ってしまう
- `DE` と自分のコールサインを落とす
- まだ交信が続くのに `<SK>`（交信終了）を打ってしまう
- 呼ぶ段階でいきなり交換内容を送ってしまう
- レポートを交換する前に `73` を出してしまう

相手の送信では、まず音だけを聞かせ、そのあと本文・用語の意味・
**その反応が何を意味し、次に何をすべきか**を表示します。

選択肢に答えたあとは「実際に送る内容」の下に **「パドルで打ってみる」** の枠が出て、
その内容を自分で打てるかをその場で試せます（任意）。打った符号は解読されて表示され、
「お手本と照合する」で文字単位の差分が出ます。打たずに次へ進んでもかまいません。

**実技（パドルで打つ）**（型を手に覚えさせる段階）

解説を見ながら、自分の送信は実際にパドルで打つモードです。呼び出しから `73` までを
通しで運用します。ターンごとに手本と照合して採点し、終了時に平均一致率が出ます。
ガイド付きの打鍵欄と違い、こちらは成績が記録に残ります。

**聞き取り練習**（実力を試す段階）

相手の送信を聞き取り、ログシート（コールサイン・RST・名前・QTH・リグ・アンテナ・天気）に
書き取ると、項目ごとに採点されます。**受信中は相手の送信を画面に出しません**（既定）。
流れている文字や語の意味が見えると答えが分かってしまうためで、
必要なら「受信中に相手の送信を表示する」で入にできます。

**相手の反応のゆらぎ**

型どおりに進むだけでなく、実際の交信で起こることを差し込めます。
「おまかせ」にすると毎回変わります。

| 反応 | 相手の送信 | 意味 |
|---|---|---|
| 名前を聞き返される | `PSE NAME AGN?` | 名前だけ取れなかった。名前だけ繰り返せばよい |
| ゆっくり頼まれる | `QRS PSE QRS` | 速すぎる。速度を落として送り直す |
| コールサインを取り違えられる | 別のコールで呼ばれる | 訂正しないと相手のログが誤ったまま残る |
| 呼び出しを取ってもらえない | `QRZ?` | 自分のコールをもう一度打つ |
| 手短に切り上げたい | `SRI QRU PSE 73` | 設備の話は省いて締めに向かう |

**型の早見表**

パネル内にいつでも開けるチートシートがあります。呼び出しから締めまでの
6 段階について、送信例・各語の意味・その段階のコツをまとめています。
送信例には自局のコールサインが当てはめられます。

### 聞き取りドリル
- **コッホ法** — 2 文字から始めて、正答率 90% を超えたら 1 文字ずつ増やします
- **頻度順** — 英文での出現頻度が高い文字から練習します
- **コールサイン / 略語・Q 符号 / 数字・RST / 頻出単語**

文字単位で採点し、間違えた文字は「苦手な文字」として蓄積されます。

### コンテスト運用（Morse Runner 準拠）

[Morse Runner](https://github.com/VE3NEA/MorseRunner)（VE3NEA）の設計を移植しています。
相手局は「コールサインを再生する機械」ではなく、状態を持ったオペレーターとして動きます。
取り違えれば訂正を求め、待たせすぎれば忍耐が尽きて去ります。

**運用モード**

| モード | 内容 |
|---|---|
| パイルアップ | CQ に複数局が同時に応答。取る力を鍛える基本モード |
| シングルコール | 1 交信につき 1 局。入力操作に慣れるためのモード |
| WPX コンテスト | 条件固定・30 分。プリフィックスがマルチになり、得点 = 有効 QSO × マルチ |
| HST 競技 | IARU 高速電信競技の形式。妨害の無い条件で速度と正確さを競う |

**ファンクションキー**

| キー | 動作 |
|---|---|
| `F1` | CQ |
| `F2` | 相手のコールとナンバーを送信 |
| `F3` | TU（交信確定・ログ記録） |
| `F4` | 自局コールサイン |
| `F5` | 相手コールサイン |
| `F6` | QSO B4（重複交信の指摘） |
| `F7` | `?`（再送要求） |
| `F8` | `NR?`（ナンバー再送要求） |
| `Enter` | 状況に応じて F2 / F3 |
| `Space` | 呼んでいる局からコールサインを補完 |
| `Tab` | 入力欄の移動 |
| `Esc` | 送信を止めて入力欄を消去 |
| `↑` `↓` | RIT を回す |

**相手局の速度**

呼んでくる局の速度を、自局の速度とは別に設定できます（10〜45 WPM）。局ごとの
ばらつき（0〜±12 WPM）も指定でき、0 にすると全局がそろいます。運用中の変更は
次に CQ を出したところから効きます — すでに呼んでいる局の速度は変わりません
（実際の交信でも相手の手は変えられないため）。

**相手オペレーターの状態機械**

`osNeedQso → osNeedNr → osNeedCall / osNeedCallNr → osNeedEnd → osDone`（または `osFailed`）
と遷移します。打ち込んだコールサインは 3 段階で照合され、完全一致なら交換に進み、
惜しい場合は相手が自分のコールを打ち直して訂正を促します。応答が無いまま
待たされると忍耐度が減り、尽きると諦めて去ります。

**LID（下手な運用者）**

`LID` を有効にすると、一部の局が次のような癖を持ちます。

- 他局の交信中に割り込んで呼ぶ
- 符号を打ち間違える
- ありえない RST（339 など）を送ってくる
- 正しく取ったのに訂正を求めてくる
- 自分宛でないのに応答してしまう
- 何度も同じことを繰り返す

**受信系**

- **RIT** — ±500 Hz。回すと周波数のずれた局ほど音程が動きます
- **受信帯域幅** — 100〜2000 Hz。バンドパスを 2 段重ねた CW フィルタで、絞ると帯域外の局が落ちます
- **QSK** — オフにすると、自局の送信中は受信音が絞られます
- **QRM** — 別の周波数で延々と CQ を出している局として実装しています

**採点**

Morse Runner の `CheckErr` と同じ優先順位で、NIL（該当局なし）→ コールサイン違い →
DUP（重複）→ RST 違い → ナンバー違い を判定します。素点（打ち込んだ全交信）と
確定点（誤りを除いたもの）を並べて表示し、5 分ごとの交信数をヒストグラムにします。
毎時ペースは直近 5 分間の窓で算出します。運用ごとのハイスコアも残ります。

運用そのものを録音して保存することもできます。

### パドル送信（エレクトロニックキーヤー）
パドルをマウスの左右クリックに変換して接続している環境を想定しています。
キーボードの `Z` / `X`、タッチ画面では打面の左右半分でも打てます。

- **利き手** — 右手用（左ボタン＝短点）／左手用（右ボタン＝短点）
- **モード** — アイアンビック B / アイアンビック A / ウルティマチック / 縦振り電鍵
- **ウェイト** — マークとスペースの比率（35〜65%、標準 50%）
- **速度** — 5〜28 WPM（手で崩れずに打てる範囲に練習を収めるため上限を 28 にしています。
  コンテスト運用の「自局速度」も同じ上限です）
- 打った符号はその場で解読され、課題（コールサイン・略語・定型文）と文字単位で照合します

#### 右手用・左手用について

パドルを同じ向きに置いたまま、右手で操作すると**左のレバーに親指**が、
左手で操作すると**右のレバーに親指**が当たります。CW では親指を短点に
割り当てるのが一般的なため、左手で打つ場合は短点と長点の割り当てを
右手用とは逆にする必要があります。「利き手」を切り替えると、この入れ替えが
マウスボタン・キーボード・タッチのすべてに反映され、パドル欄の表示も
追従します。

親指を長点にしたい場合は「親指側を長点にする」も併用できます。
利き手と組み合わせて 4 通りの割り当てから選べます。

| 利き手 | 親指 | 左ボタン | 右ボタン |
|---|---|---|---|
| 右手用 | 短点 | 短点 | 長点 |
| 左手用 | 短点 | 長点 | 短点 |
| 右手用 | 長点 | 長点 | 短点 |
| 左手用 | 長点 | 短点 | 長点 |

パネル先頭に **13 ステップのチュートリアル**があります。短点・長点の連続送出から
スクイーズ、モード A と B の違い、ウェイトと速度の合わせ方まで、実際に打って
条件を満たすと自動で次に進みます。

### 初心者モード
送信中の Q 符号・略語・RST・コールサインを、その語が流れているタイミングで
リアルタイムに解説します。本文中の用語は種類ごとに色分けされ、マウスを乗せると
意味が出ます。RST は「599 = 了解度5:完全 / 強度9:極めて強い / 音調9:完全な純音」のように
桁ごとに展開されます。

聞き取りの答えが部分的に見えるため、実力を試すときは設定でオフにしてください。

### バンドコンディション
QRN（空電）・QSB（フェージング）・QRM（混信）・フラッターを個別に切り替えられます。
フェージングは局ごとに独立してかかり、混信は別周波数で CQ を出し続けている局として
鳴ります。

### 画面構成
- **右側は常にパドル欄** — ヘッダーとタブの下から画面下端まで。打面・送信速度・
  打った符号の解読・要素の流れを、どのタブでも表示します。たたむ操作は持ちません。
  **打面はこの 1 か所だけ**で、パドル送信タブに二つ目の打面は置いていません
- **ヘッダーとタブは固定** — 本文とパドル欄がそれぞれ内側でスクロールします
- **一時停止・再開・終了** — 画面上部の 2 つのボタンで、どのタブでも同じように効きます。
  一時停止は AudioContext ごと止めるので、再開すると符号の途中から続きます。
  終了はタブごとに練習を開始前の状態へ戻します。`Space` / `Esc` でも操作できます

### その他
- **変換・電鍵** — 任意の文章をモールスに変換して再生、縦振り電鍵の練習
- **略語集** — 約 70 語の Q 符号・略語の対訳。クリックで音を確認
- **記録** — ドリル・交信・送信・コンテストの成績と苦手な文字を localStorage に保存

## 速度の考え方

文字速度（char WPM）と実効速度（effective WPM）を別々に設定できます。
ARRL 方式のファーンズワース・タイミングで、**各文字は速いまま、文字間と語間だけを
広げます**。文字の響きを速度ごと覚え直さずに済むため、初学者はこの方式が推奨されます。

例えば文字速度 20 WPM・実効速度 10 WPM なら、一つ一つの文字は 20 WPM の速さで
鳴りますが、全体としては 10 WPM のペースになります。慣れてきたら実効速度を
文字速度に近づけていってください。

## テスト

実際の Chromium を自動操作して、全機能を通しで動かす E2E テストがあります。
モールス音の生成やキーヤーのタイミングはブラウザの中でしか再現できないため、
単体テストではなく実ブラウザで検証しています。

必要なもの: Node.js 18 以上、`python3`、Playwright + Chromium。

```bash
# 作業ツリーをそのまま検証する
tests/run-e2e.sh

# スイート名を指定して一部だけ実行する
tests/run-e2e.sh core keyer-tutorial

# 公開中のページの実ファイルを取り寄せて、そのバイト列を検証する
BASE=https://hidetako.github.io/CWtraining tests/run-e2e.sh --remote
```

`npm test` でも同じものが走ります。説明書の Word 版を作り直すときは
`npm run docs`（`docs/MANUAL.md` を編集したあとに実行してください）。

`--remote` は公開ページのファイルを一時ディレクトリへ取得してから
ローカルで配信します。ブラウザから直接公開 URL を開くのではなく取得した
実体を検証する形にしているのは、ネットワーク制限下でも同じ手順が通るように
するためです。検証対象は公開中のファイルそのものなので、
「手元では動くが公開版では動かない」を検出できます。

| 環境変数 | 既定値 | 用途 |
|---|---|---|
| `BASE` | `http://localhost:8123` | `--remote` のときの取得元 URL |
| `PORT` | `8123` | 検証用サーバーの待ち受けポート |
| `PW` | Playwright の既定の場所 | `playwright/index.mjs` の絶対パス |
| `SHOTS` | 一時ディレクトリ | スクリーンショットの出力先 |
| `VERBOSE` | 未設定 | 設定すると各スイートの出力を全部表示する |

各スイートは検出した不具合の数を終了コードとして返します。
ページ上の JavaScript エラーと `console.error` も失敗として扱うので、
表示は正しいが裏でエラーが出ている、という状態も落ちます。

| スイート | 検証する範囲 |
|---|---|
| `core` | 交信シミュレーター・ドリル・コンテスト・キーヤー・略語集・初心者モードの通し |
| `guided-qso` | ガイド付き模擬交信の選択肢・解説・型の早見表 |
| `guided-keying` | ガイド付きの「パドルで打ってみる」欄（打鍵・照合・打ち直し） |
| `live-qso` | 実技モードで実際に打鍵して採点まで進む |
| `contest` | Morse Runner 準拠の運用モード・採点・自己ベスト |
| `keyer-tutorial` | チュートリアル 13 ステップの進行と達成判定 |
| `paddle-hand` | 利き手・親指の割り当てと保存 |
| `tx-tone` | 送信音の周波数設定と受信音からの独立 |
| `wpm-cap` | 送信速度の上限 28 WPM（つまみ・API・保存値・コンテストの自局速度） |
| `layout-transport` | パドル欄の位置と大きさ、一時停止・再開・終了、聞き取りの既定表示 |
| `contest-dx-wpm` | コンテストの相手局速度（基準・ばらつき・運用中の変更・HST） |
| `improvements` | タブのキーボード操作、記録の書き出し・読み込み、推移グラフ、苦手集中ドリル |

## 動作環境

Web Audio API に対応したブラウザ（Chrome / Edge / Firefox / Safari）で動作します。
音を鳴らすには最初に画面のどこかを操作する必要があります（ブラウザの自動再生制限のため）。
設定と成績はブラウザの localStorage に保存され、外部には送信されません。

**パソコン向けの画面です。** 右側をパドル欄に固定しているため、横幅 1000px 以上を
想定しています。スマートフォン向けの段組み切り替えは持っていません。
